### Фаззинг-тестирование

Unit-тесты проверяют то, что разработчик заложил в сценарий. Фаззинг делает наоборот — подаёт случайные, граничные и заведомо некорректные данные, чтобы найти неочевидные падения.

**Бэкенд: Hypothesis.** Для Django-приложений выбрана Hypothesis. Стратегии описывают, какие данные генерировать: `usr = text(min_size=0, max_size=150)` — строки от пустой до 150 символов. Декоратор `@given` подставляет их в тест. Если тест падает, Hypothesis сам находит минимальный пример, который воспроизводит проблему, и сокращает его (shrinking).

(Рисунок 1 — фаззинг-тест регистрации и логина: `backend/core/fuzz_tests.py`, строки 34–49)

Всего 42 теста. Они покрывают авторизацию, CRUD для properties/meters/readings/payments, аналитические эндпоинты и ключевые функции сервисного слоя — `process_reading`, `find_tariff`, `forecast_property`. Каждая итерация `@given` выполняется в отдельной транзакции: за это отвечает `hypothesis.extra.django.TestCase`.

(Рисунок 2 — тест сервисного слоя с бизнес-инвариантом: `backend/core/fuzz_tests.py`, строки 254–274)

**Фронтенд: fast-check.** React-компоненты тестируются fast-check под Vitest. Библиотека генерирует произвольные пропсы — массивы разной длины со случайными именами, адресами, серийными номерами. Отдельные тесты подставляют в ответы API «мусор»: null, undefined, NaN, строку вместо числа.

(Рисунок 3 — фаззинг-тест Dashboard с мусорным ответом API: `frontend/src/__tests__/Dashboard.test.tsx`, строки 44–65)

Перед каждым property-тестом окружение сбрасывается через `cleanup()`, моки API обновляются. Строки с `[` и `{` подаются через `fireEvent.change`, а не `userEvent.type` — последний интерпретирует их как спецпоследовательности и падает.

(Рисунок 4 — покрытие после внедрения фаззинга)

Четыре ошибки в боевом коде фронтенда нашлись на первом же прогоне:
- `readings.slice is not a function` — API вместо массива вернул null;
- `data.forecast_amount.toFixed is not a function` — forecast_amount пришёл строкой;
- `formatMonthLabel` кидал `Invalid time value` на некорректных строках даты;
- коллизия прототипа в `groups[month].push` — строковый ключ совпал с унаследованным методом.

После фикса багов покрытие бэкенда — 91%, фронтенда — 68%. Фаззинг прогоняется на каждый push: Hypothesis с PostgreSQL в Docker, fast-check в Node 20.
